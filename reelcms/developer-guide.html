Architecture

Three processes: a Vue single-page app, a Spring Boot API, and MongoDB running as a single-node replica set. The frontend never talks to MongoDB, and the API never renders HTML.

What makes the shape interesting is the second path. Ordinary reads and writes go browser → API → database and back. But the admin dashboard's live counters travel the other way: MongoDB pushes each write to the API through a change stream on the oplog, and the API forwards it to connected browsers over server-sent events. Nothing polls, anywhere.

The data model

Six collections. MongoDB has no foreign keys, no joins at write time and no cascade — so every relationship below is a convention the application enforces, and the interesting question for each one is embed or reference.

Collection Holds Notes
reels The aggregate root — one document per reel Carries its video, tags, stats and a creator snapshot inline
creators The canonical public profile Referenced from reels, comments and view events
comments One document per comment Separate collection because the count is unbounded
reel_collections Curated highlight sets Named to avoid "collection" meaning two things in one sentence
view_events One document per playback Time-series collection, 90-day TTL
users Sign-in accounts Separate from creators — an admin is not a creator

Embed or reference

One rule decides all six cases: embed what is bounded, reference what grows. Applied to reels, it produces this:

Field Choice Why
video embedded 1:1 with the reel, and no query wants a video without its reel. A join would buy nothing.
tags embedded A handful, forever. Always displayed, and a multikey index makes {tags: "nba"} an index seek.
stats embedded Four counters moved with $inc — atomic on a single document, no transaction needed.
creator both Referenced by id, with three display fields copied so the feed needs no $lookup. See below.
collectionIds referenced Many-to-many, and collections are edited independently of the reels in them.
comments referenced Not a field at all — its own collection. This is the decision that matters most.
Why comments are not an array

Embedding them is the instinct, and for a small blog it is right. Here it fails three ways at three different scales: a document is capped at 16 MB, so a viral reel eventually cannot accept another comment; every feed query would read the entire thread off disk to render a card that shows none of it; and appending to an array rewrites the document while stats is being $inc'd on every view.

The creator snapshot, and what it costs

Every reel carries a copy of its creator's username, displayName and avatarUrl. The id is the source of truth; those three are a cache the application is responsible for invalidating.

What it buys: the public feed — the hottest query in the system — stays a single index scan over one collection, with no join.

What it costs: renaming a creator has to rewrite that copy on every reel they own. CreatorServiceImpl.update() does it in one statement, and the admin dialog tells you how many reels are about to be touched — the trade is shown to the person paying it, not hidden. 

// ReelDAOImp — the bill for denormalization, paid in one statement
mongo.updateMulti(
    Query.query(Criteria.where("creator.id").is(creatorId)),
    new Update()
        .set("creator.username",    username)
        .set("creator.displayName", displayName)
        .set("creator.avatarUrl",   avatarUrl),
    Reel.class);

The rule of thumb: denormalize fields that are read constantly and change rarely. A display name qualifies. followerCount does not — it moves every minute, and is deliberately left out of the snapshot.

Indexes

All declared in one file, MongoIndexConfig, created at startup from @PostConstruct. Not with @Indexed annotations: auto-index-creation is off, because an annotation that silently triggers an index build against a live collection is a production incident that starts as a one-line diff.

Collection Index Serves
reels { status: 1, publishedAt: -1 } The public feed — the hot path
reels { "creator.id": 1, status: 1, publishedAt: -1 } A creator's own reels
reels { slug: 1 } unique Permalinks, and the slug-collision guard
reels { tags: 1, publishedAt: -1 } Multikey — browse by tag
reels text: title 10, tags 8, description 5 Search. Weights decide ranking across fields
comments { reelId: 1, createdAt: -1 } A reel's thread
creators { username: 1 } unique Profile permalink
users { email: 1 } unique Login

Field order in every compound index follows ESR — Equality, then Sort, then Range. Get it backwards and MongoDB can still use the index, but it sorts the results in memory afterwards, which is capped at 32 MB and fails outright on a large result set. Verify with .explain(): you want an IXSCAN with no SORT stage above it.

One text index per collection

A collection may have at most one text index. It can cover many fields, as this one does — but you cannot add a second later for a different field set. The create fails with IndexOptionsConflict.

Backend

Layered the same way as the pizza demo, so the two can be read side by side. One package per document, everything for it together — entity, repository, DAO, service and controllers all live in the same folder.

The DAO rule

Every DAO is an interface plus an implementation, and the implementation reaches for a Spring Data repository or MongoTemplate — whichever each method needs. This is the same split pizza keeps between a repository and JdbcTemplate.

Repository

Anything Spring Data can derive from a method name — findBySlug, existsBySlug, findByStatusOrderByPublishedAtDesc.

MongoTemplate

Dynamic filters, $text search, aggregation pipelines, and every partial update.

Never save() a counter

A counter change is always $inc. Load-mutate-save loses increments under concurrency and rewrites the whole document.

Two deliberate departures from pizza

  • No MapStruct. EntityDtoMapper is hand-written. The interesting question here is which document fields reach the wire — User.passwordHash being the one that matters — and a generated mapper hides exactly that.
  • No Liquibase. There is no schema to migrate. MongoIndexConfig takes its place, and is the file to read to understand the query strategy.

The one place the app talks to a backend

Every component imports api from src/api/index.js. Nothing imports mock.js or http.js directly — which is what keeps switching data sources a one-line change instead of a hunt through thirty components. 

// src/api/index.js
import { mockApi } from "./mock";
import { httpApi } from "./http";

export const usingMock = import.meta.env.VITE_USE_MOCK !== "false";
export const api = usingMock ? mockApi : httpApi;

The whole UI was built against mock.js before the backend existed, which is why the mock defines the contract rather than imitating it. The two modules must stay method-for-method identical. A badge in the admin header always shows which one is live — getting that wrong is the most confusing state to debug.

Key flows

Feed pagination — cursor, not skip

The feed pages by cursor. In an infinite scroll this is not a micro-optimisation; it is the difference between a feed that stays fast and one that degrades the longer someone reads.

The client sends back the id of the last reel it received; ReelServiceImpl.feed() resolves it to a publishedAt and seeks from there. A full page implies there is probably more; a short page proves there is not. The worst case is one extra request that returns nothing — far cheaper than counting the whole collection on every load just to be exact.

Recording a view

One user action, two writes, and the dashboard update comes free. The split between the event log and the counter is the design, not an accident.

The two can drift, and that is accepted: a view count is a vanity number, not a ledger. If it had to be exact you would rebuild it from the events on a schedule rather than pay for a transaction on the hot path — which is exactly what DataSeeder.reconcileStats() does at seed time.

The dashboard

Every figure comes from a pipeline over real data. No hard-coded numbers anywhere — the same rule pizza's reports follow.

PanelPipeline
Views over time$match ts → $lookup reels → $group by $dateTrunc day → $sort
Top reels$group by reelId → $sort → $limit → $lookup → $unwind
Engagement by tag$match published → $unwind tags → $group → $sort
Completion rate$lookup for duration → $group with $avg of $min(1, watch / duration)
Trending tags$unwind → $group → $sort → $limit

Stage order is deliberate. The $match on ts comes first so the time-series collection can skip whole buckets, and only surviving events are joined. In Top reels, the big collection is aggregated down to ten rows before the $lookup — putting the join first would join every event ever recorded and then throw most of it away.

Stages the fluent builder handles well use it; the rest use Aggregation.stage(json), which is copy-pasteable straight into mongosh — and unlike nested new Document(...) calls, does not reject nulls in surprising places.

Auth & roles

Stateless JWT, 12-hour expiry, HS256. JwtAuthenticationFilter reads the bearer token, builds an AuthPrincipal from its claims, and puts it in the security context — so an authorization decision never needs a database round trip.

ADMIN

Everything. The only role that may manage creators or reassign a reel to a different one.

CREATOR

Manages only reels whose creator.id matches their own creatorId. Enforced server-side; the UI just avoids offering buttons that would 403.

Anonymous

The whole public surface, including posting comments, liking and recording views.

Two things that look like bugs but are not

CSRF is disabled — correctly. CSRF protection defends a cookie-authenticated session, because the browser attaches cookies automatically. A bearer token has to be added by script, so it is itself the defence. This would not be true if the API used a session cookie.

The SSE endpoint takes its token in the query string. EventSource cannot set request headers — a browser API limitation, not an oversight. It is scoped to that one path deliberately, since a token in a URL ends up in access logs.

The token is kept in localStorage, which is a demo choice and the wrong one for production: any XSS on the page can read it. A real deployment puts it in an httpOnly SameSite cookie. It lives in src/api/session.js, a leaf module that exists so the HTTP client and the Pinia auth store can share it without importing each other.

Three terminals. Start the database first — the API seeds itself on first boot.

Nothing is stubbed in either suite, and there is no embedded MongoDB. Almost everything worth testing here is behaviour of the actual server — $inc atomicity, $lookup type matching, text-index ranking, time-series inserts, change streams. A fake would either not implement them or implement them differently.

Traps

Every one of these was hit while building the app, and each is commented at the place it bites. They share a family resemblance: nothing throws. The failure mode is silence.

SymptomCause
Connection refused on 27017 — a port in no config file Spring Boot 4 renamed spring.data.mongodb.uri → spring.mongodb.uri. The old key is ignored silently and the driver falls back to its default.
Integration tests deleted the demo data spring.mongodb.database was set alongside a URI that already named one. The standalone property wins, so the test's URI override did nothing.
Three reports returned empty arrays, no error $lookup compares types strictly. A String reelId is a BSON string; the _id it points at is an ObjectId. Fixed with @Field(targetType = OBJECT_ID).
Change stream opened cleanly and delivered nothing filter(Aggregation) is field-mapped against the domain type, and operationType is a change-event field, not a Reel field. Use filter(Document...).
Change-stream event bodies were all null An update event carries only the changed fields unless you ask for fullDocument: updateLookup.
view_events created as an ordinary collection DataSeeder is an ApplicationRunner, which fires before ApplicationReadyEvent. Index setup moved to @PostConstruct. A collection cannot be converted to time-series after the fact.
A timestamp changed between the POST response and a later GET BSON keeps milliseconds; Instant.now() has microseconds. Everything routes through Timestamps.now().
Driver hung with a ServerSelectionTimeout that never mentioned ports A replica set hands back its member list and the driver reconnects to that address. The advertised host:port must be reachable under that exact spelling — hence publishing 27018 → 27018.
Login form said "your session expired" on a wrong password A 401 was treated as expiry regardless of whether a token had been sent. With a token it is an expired session; without one it is a failed login.
Both "Dashboard" and "Reels" highlighted at once Vue Router marks a link to an index child active whenever any sibling is.
A broken poster stretched a table row to 200px "4th & Inches" — a raw ampersand makes an inline SVG malformed, so the browser fell back to alt text.
The habit these teach

MongoDB is permissive by design: it will accept a string where you meant an ObjectId, create a collection you did not configure, and run a pipeline that matches nothing — all without complaint. When a query returns an empty array, check the types before you check the logic.
